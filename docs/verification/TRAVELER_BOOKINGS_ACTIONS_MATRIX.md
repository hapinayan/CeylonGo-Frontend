# Traveler Bookings Phase 02 Actions Matrix

Audited against backend f795562 and the mounted router source. Paths below start at /api/v1. The unified Traveler Bookings UI adds only authenticated, read-only lookups after loading the current booking. Server authorization remains authoritative.

| Service | Cancellation contract reviewed | Payment, refund and contact coverage |
| --- | --- | --- |
| Homestay | POST /bookings/{id}/cancel. Authorized owner/manager/admin, pending/awaiting payment/confirmed, with in-lock validation. Paid cancellation uses the booked cutoff and qualified capture. | Shows booked nightly rate, recorded payment and cancellation data. Optional GET /homestays/{listingId}/contact uses the public listing publication predicate and an ID from the owned detail. The homestay payment-status endpoint exists; the detail snapshot remains the displayed source. No refund request or receipt action. |
| Activity | POST /activity-bookings/{id}/cancel. Traveler owner, pending/confirmed and unpaid pay-at-location under the temporary rule. | Shows payment snapshot, participant count and recorded cancellation reason/time when supplied by owner history. No traveler-only receipt, refund-history or contact route verified for this booking. Dates and listing title remain unavailable when absent from the activity history response. |
| Eco-Tourism | POST /eco-reservations/{id}/cancel requires an owned future unpaid pending/confirmed reservation and enforces the applicable cutoff. Paid online cancellation has a separate POST /payments/cancel under that reservation. | Payment uses the reservation snapshot. Optional owner-scoped GET /eco-reservations/{id}/payments/refunds displays the backend amount, currency and state. The separate payment status read remains available to the existing Experiences flow. No refund execution, receipt or contact control. |
| Tour Guide | POST /tour-guide-bookings/{id}/cancel authorizes the traveler and validates state. Eligible paid online cancellations can set refund_pending. | Shows the server eligibility estimate from detail, separately from refund history returned by GET /tour-guide-bookings/{id}/payment/status. Optional GET /tour-guides/{guideId}/contact displays the approved business phone only when the guide ID matches and the backend confirms an authenticated view. Raw gateway IDs, commission and private fields are omitted. |
| Bike Rental | PATCH /rental-bookings/{id}/cancel. Owner, pending/confirmed before pickup and server-applied fee/refund rules. | Shows recorded payment, daily rate and deposit when furnished by detail. Deposit status and booking payment status stay separate. Rental provider contact and deposit-history source exist. The UI defers rental contact because its standalone read has weaker listing publication checks, and creates no receipt from a provider-only cash collection action. |
| Artisan | POST /artisan-reservations/{id}/cancel. Actor authorization, active reservation, unexpired hold and no payment or capture under lock. | Shows item/quantity, recorded payment, pickup date, business name and cancellation reason/time when supplied. The audited traveler item reservation does not supply a dedicated receipt/contact/refund history view. |

A booking total, payment snapshot, refund eligibility estimate and refund ledger state are distinct. The UI does not infer that a payment was received or that a refund settled. No verified generic traveler receipt download was found. The demonstration cancellation is restricted to selected upcoming unpaid pending/confirmed sample bookings. It requires confirmation and updates only the in-memory preview record keyed by service and original ID. This demonstration rule is not a live cancellation policy.
